# mooncassette playground

浏览器里的 mooncassette 交互式演示：载入一份 cassette，看它里面有什么、两份录制
哪里不同、一条请求为什么匹配不上、以及密钥在落盘前被抹成了什么。

**在线版本**：<https://mihujiang.github.io/mooncassette/>

## 它是一个独立模块

这里自带 `moon.mod`，用 `moon add weopqrst/mooncassette@0.4.0` 引入本库，而不是
引用仓库里的本地代码。这不是形式上的讲究 —— `moon.mod` 只接受注册表里带版本号的
依赖，本地路径依赖不被支持。于是它天然成为「别人真的会 `moon add` 这个包」的证据：
它就是一个真实的下游消费者。

它必须独立成模块还有第二个原因：`extern "js"` 在 wasm-gc 后端不受支持，而这个
页面需要操作 DOM。若把 demo 放进父模块的包树里，父模块的
`moon check --target wasm-gc` 会直接失败。因此仓库的 `.gitignore` 忽略了 `demo/`
与 `docs/`（moon 的打包与包发现都遵循 `.gitignore`），这两处的内容用
`git add -f` 单独保留在仓库里。

## 本地运行

页面用的是 ES 模块，`file://` 打开会被浏览器的同源策略挡住，需要一个 HTTP 服务：

```bash
bash demo/build.sh          # 编译 + 跑测试 + 产出到 docs/
cd docs && python -m http.server 8080
# 打开 http://localhost:8080
```

只想快速看一眼而不构建：

```bash
cd demo && moon build --target js --release && node test/smoke.mjs
```

## 验证方式

不靠「打开浏览器点一遍」——那种验证不可重复，改动之后也不会自动重跑。

| 层 | 测什么 | 怎么跑 |
|---|---|---|
| 纯逻辑（`main/logic_wbtest.mbt`） | 转义、整数解析、状态机、五个视图的渲染输出 | `cd demo && moon test --target js` |
| 端到端（`test/smoke.mjs`） | 真实构建产物 + 桩 DOM：点按钮、切视图、断言渲染结果 | `node test/smoke.mjs` |

冒烟测试同时验证产物里**不含** `node:` / `require(` / `process.` / `Buffer.` ——
只要出现其中一个，页面在浏览器里就会直接报错，而仓库里其它检查都发现不了这件事。

## 五个视图

| 视图 | 回答的问题 |
|---|---|
| 概览 | 这份录制里有哪些调用、各是什么形态（整段 / 流式 / 被限流） |
| 单条详情 | 某一次调用的完整请求、响应，以及流式帧序列 |
| 漂移对比 | 两份录制之间，哪些调用**请求没变而响应变了** |
| 未命中诊断 | 贴一个请求，看它差在哪个字段上（只报路径，不回显字段值） |
| 脱敏预览 | 密钥在落盘前被抹成了什么 |

## 几个刻意的设计

- **渲染是纯函数**：状态进、HTML 字符串出。因此界面行为可以断言，不必开浏览器。
  界面上的可变状态只有一个 `AppState`，没有中间态。
- **所有文本都经过转义**：页面渲染的是外部文件的内容。一份含 `<script>` 的
  cassette 直接拼进 `innerHTML` 就会执行，冒烟测试里有一条专门守这个。
- **脱敏预览默认不显示原文**：那份原文可能含真实密钥，而用户载入的正是「还没
  脱敏的文件」。页面不出网，但屏幕会被截图、会被投屏，所以默认隐藏、按需显示。
- **诊断只报路径、不回显字段值**：诊断结论常被贴进 issue 或日志，而其中的请求
  未必脱敏。这与库本体的取舍一致。
- **输入框放在静态 HTML 里**：整块重渲染会把光标顶回开头，边打字边重渲染等于
  没法输入。因此请求输入框不参与重渲染，只切换显示与否。
